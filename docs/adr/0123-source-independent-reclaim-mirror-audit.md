# ADR 0123 — Source-scope-independent verification of signed terminal reclaim history

- **Status:** M4 internal-only, **read-only historical audit**. This does not authorize metadata deletion, restoration, cleanup, Core startup, import, publication, CLI/TUI/API or GC.
- Extends ADR 0119–0122. SQLite remains **v18**. Original ciphertext, credential SQLite, live Applied/LKG/selection/declaration/Core and rule-tree formats are unchanged.
- Ordinary-user Linux, no TUN. Original CN 28 preset groups and Custom → GeoSite → GeoIP → ACL → FINAL remain intact; subscription/ISP routing is not reintroduced.

## Problem and strict boundary

ADR 0122's complete signed proof mirror preserves the original deletion plan, every HMAC per-leaf intent, the sealed completion, and the independent ADR 0121 attestation **outside the inactive reclaim directory**. However, the existing `InspectMirroredReclaimEvidence` still demands all source-scope audit files be on disk. That reader cannot distinguish *historical proof integrity* from *current source-folder integrity*, and a future operator might mistakenly infer that a signed mirror proves all original files are currently absent.

We introduce a separate **source-scope-independent, cryptographic history-only audit**. The archived plan and completion prove which actions were signed in the past. **They do not prove the current existence/absence, durable release of disk blocks, or safety of deleting a particular inode.** Even a successful detached inspection of a missing source directory grants no new destructive authority.

## Decision

1. `InertRestoreResourceLease.InspectDetachedReclaimMirror(ctx,key)` has no caller-specified pathname or rollback/deletion flag, and never opens, lists, stats or requires the original `inert-rule-bundles` directory/scope. Reuse the exact originally prepared v18 ciphertext record, explicit nonzero 32-byte original key, candidate directory `flock` and lease mutex. Recheck full ciphertext HMAC/SHA, original in-memory archived SQLite/schema/profile, immutable inventory, prepared journal and live Applied/LKG/declaration/selection/Core CAS before, during and after the read.
2. Derive only the **existing** UID-owned private 0700 SQLite-state parent via no-follow pinned component descriptors. Read both the `.ktui-inert-reclaim-attest-v1-<archive-sha>` and `.ktui-inert-reclaim-mirror-v1-<archive-sha>` one-link regular 0400 files with descriptor-relative `O_NOFOLLOW`, strict bounded sizes (2048 bytes anchor, 256 KiB mirror) and current UID/mode/inode checks. No create, chmod, rename, unlink or fsync occurs in the inspector.
3. Parse **canonical exact JSON**, not merely permissive JSON with duplicate fields/unknown names. Independently authenticate the external attestation's HMAC, the entire mirror's separately domain-separated HMAC, the embedded original plan HMAC, terminal completion HMAC and **each** indexed intent HMAC with the same supplied original key and the correct distinct domains, using constant-time MAC comparison. Require all mirror-embedded canonical plan/completion/attestation bytes and SHA-256 values to match the signed bounds and the real external attestation.
4. Reconcile the original sorted 1–128 inventory of exact SHA/length/name rule leaves against the signed plan, exact still-prepared journal ID, original scope device/inode and rule inode metadata. Compute original absent byte sum from bounded signed rule lengths, not a caller-supplied count. Require every three-digit indexed intent in original order and compare its keyed MAC to the precise plan digest/index/rule basename. Require terminal completion and off-scope attestation to bind the same plan/archive/inventory/journal/scope and counts. Any mismatch, unexpected extra intent, missing proof or malformed digest fails closed.
5. Read the two private off-scope proofs **twice** under the same ciphertext lease, compare each file's inode identity and complete authenticated historical report, and repeat the full live CAS and pinned parent checks. Do not infer that a past HMAC means the source directory was safely removed or was ever absent after a filesystem power loss.
6. Return only digests and counts, documented original absent byte lengths, `ArchiveJournalVerified=true`, `HistoryMACsVerified=true` and `RequiresRevalidation=true`. Always return `SourceScopeVerified=false`, `RuleAbsenceVerified=false`, `DeletionAuthorized=false`, `RestoreSupported=false` and `RestoreReady=false`. These are **explicit negative safety guarantees**, not unsupported optimistic defaults. On any failure return a zero report.
7. Keep the older **source-bound** `InspectMirroredReclaimEvidence` unchanged and fail-closed for missing source proofs; it remains the only available complete original-content reinspection. Neither reader removes a file or adopts an orphan. No general orphan GC, automatic retention expiration, pending-rule directory cleanup, or operator-facing command is enabled.

## Regression gates

- A complete signed mirror is generated under ADR 0122. Rename the original private staging root **without deletion**; ensure the source-bound reader refuses while the detached historical reader verifies the mirror with a newly acquired ciphertext lease and unchanged live SQLite/prepared journal.
- Refuse missing/symlink/public/hard-linked/tampered mirror or attestation, wrong key, canceled/closed lease, abandoned prepared journal, or stale selection/live CAS, returning no sensitive data and no success report.
- With the original archive key in tests, **re-sign an otherwise deliberately forged mirror's outer HMAC** to show that impossible rule counts, scope inode, signed plan, completion/attestation SHA, absent bytes, missing/extra indexed intent or journal ID are still rejected by **independent nested checks**.
- CI format, module, Vet, ordinary tests, complete race test and managed real-Core integration remain required before claiming this stage is validated. Real device power-loss faults T15/T23 and long soak tests remain separate open gates.

## Future gates

**Not implemented:** irrevocable transfer of physical directory identity/authority; operator-approved final plan/intent/scope removal; durable external tombstone retention and quota policy; old pending orphan resolution; power-loss T15/T23; restored credential SQLite and active rules/Core transaction; rollback-of-rollback; CN offline resource/license closure; 72-hour/7-day/30-day long-duration stability. Historical verification is not enough to eliminate any of those blockers. PR #1 stays Draft.
