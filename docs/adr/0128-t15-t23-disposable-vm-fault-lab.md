# ADR 0128 — Operator-gated disposable VM stop for T15/T23 replay preparation

- **Status:** M4 development/lab infrastructure, not production; **T15/T23 acceptance remains incomplete**.
- Depends on `docs/plan.md` T15/T23 and ADR 0124–0127. No change to SQLite v18, key custody, backup format, live Core or routing models.
- Preserve Linux ordinary-user no TUN, original CN 28 presets and Custom → GeoSite → GeoIP → ACL → FINAL routing, with subscription/ISP routing excluded.

## Motivation

The project already has extensive SIGKILL and fault-injection regression around prepared journals, encrypted archive/fsync, inactive rule intents and signed external evidence. These establish a useful process-crash boundary, but do **not** demonstrate that an actual guest device after forced power interruption can reboot, authenticate original evidence and maintain active Applied/LKG/Core safety. Explicit, repeatable guest-based fault injection is necessary before resolving T15/T23. A generic `virsh destroy` script could accidentally stop a production VM or invent power-loss pass evidence.

## Decision

1. Add **host-side only** `scripts/recovery_lab/vm_power_cut.py` with exactly four explicit intended checkpoint labels: `T15-prepared-journal`, `T15-checked-candidate`, `T23-sealed-archive-publish`, `T23-signed-reclaim-proof`. Only an independent **guest fault fixture** may create the exact phase-ready marker after the selected real checkpoint. The host code never manufactures the marker or claims it proves the checkpoint.
2. Default behavior is **preview only** with zero filesystem mutations or VM changes. The tool runs only libvirt `qemu:///session` commands, never system libvirt, sudo, shell interpolation, host process-kill, host reboot, or Core activation. Destructive operation is hard-gated by: a disposable VM-name prefix; exact 36-character lowercase UUID; single-use lowercase 128-bit nonce; already-existing current-UID `0700` private host sandbox; exact owner-private single-linked `0400/0600` marker bytes bound to case+nonce; running VM status; explicit `--execute`; and an environment acknowledgement binding domain/UUID/case/nonce. Reject root in destructive mode.
3. Keep a pinned no-follow file descriptor for the phase marker and the private witness directory; recheck contents, inode and name binding immediately before the forced VM stop. Refuse symlink/hardlink, unsafe permission, replay or stale IDs. A cooperating phase fixture must publish to an isolated host/guest channel, never normal user XDG state. Only an operator-approved cloned, disposable VM with no actual user data is an eligible target.
4. When expressly enabled, write a non-overwriting owner-0600 JSON **intent**, fsync it and its parent, then issue one `virsh --connect qemu:///session destroy --domain <disposable-name>` (not graceful), and independently require reported VM state `shut off` before writing a separate exclusive, fsynced **observation** file. After intent publication, errors and ambiguous outcomes must not cause automatic retry, repair, deletion, restart or replacement.
5. Both JSON files categorically mark `physical_power_loss_verified=false`, `post_reboot_consistency_verified=false`, `guest_boot_verified=false`, `restore_authorized=false`, and `metadata_deletion_authorized=false`. They certify only intended/observed *virtual guest stop*, not an electrical power cut, disk flush guarantees, or post-reboot recovery. A real host may buffer writes after virtual guest loss.
6. No direct connection to production backup/restore/cleanup CLI, TUI or API, no power-cut task in normal CI and no implicit acceptance of T15/T23. Manually created phase markers are insufficient to claim the target fault boundary occurred. A separate guest-side fixture and complete after-boot independent baseline comparison are prerequisites before any T15/T23 acceptance statement.
7. CI runs only standard-library **mocked** Python tests: preview unchanged, exact opt-in, root/domain/UUID/nonce refusal, permissions, symlink/hardlink, stale marker, stopped VM, one-time intent/observation with private modes and durable-write calls, and post-stop observation failure leaving an ambiguous intent with no retry. This never stops a VM and does not need privileges or libvirt on CI runners.

## Fault matrix and next gates

See [T15/T23 disposable VM runbook](../runbooks/t15-t23-virtual-powercut-lab.md) for exact sample operations, state isolation, guest checkpoint marker contract and the required post-reboot comparison of live SQLite/journal, resource inodes/SHAs, encrypted ciphertext HMAC, source-bound/detached signed proofs and Managed Core behavior. The guest fixture and forced power trials are **not yet executed**; a host-side `virsh destroy` is not guaranteed equivalent to sudden loss of host power. This ADR does not close rollback-of-rollback or physical power-loss validation. Proper offline CN resource licenses, full restored credential SQLite, complete Core Check/Activate/Verify, pending orphan reconciliation, formal metadata retention/deletion and 72h/7d/30d soak remain blockers. PR #1 stays Draft, `main` unchanged.
