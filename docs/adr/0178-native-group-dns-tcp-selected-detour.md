# ADR 0178 — native Custom Group DNS TCP Selected detour verified with real packets

- **Status:** proposed M5/T22 scoped experiment, not T22 or release completion.
- **Basis:** merged ADR 0175 Outbound/Node UDP DNS, ADR 0176 Direct destination UDP DNS and ADR 0177 Proxy TCP DNS selected transport with real independently recorded upstream SOCKS port receipts.
- **Envelope:** eighth independent `network none` SHA-approved Core/production Daemon Linux amd64+arm64 container with `--cap-drop ALL --security-opt no-new-privileges --user 10001:10001 --read-only`, fresh private /work, no TUN, public DNS, privileged 53, CN resources, subscription/ISP or extra route layers.

## Decision and audit

1. Exact V1 declaration: one Custom domain atom matching only `t24-group.invalid` in Rule inbound; application route target Direct, `dns_profile_id=group-selected-tcp`; associated Group DNS TCP profile at dedicated ephemeral 127.0.0.1 listener and **explicit** `detour_target: {kind: current_selected}`. Retain independent Proxy TCP DNS (global Selected), Direct UDP and Node UDP DNS, single IP-literal synthetic SOCKS Selected upstream, three mixed inbound ports and DIRECT FINAL. This is not a CN GeoSite/GeoIP test.
2. Extend the strict existing TCP DNS responder in an *allowlisted opt-in manner* to answer either original `t24-selected.invalid` Proxy DNS or `t24-group.invalid` Group DNS on separate servers; all other QNAMEs fail, only IN A/AAAA/HTTPS bounded DNS-over-TCP frames and loopback A=127.0.0.1. Existing seventh-container behavior remains unchanged. The original synthetic SOCKS accepts the second local Group DNS TCP port **only** when explicitly opted in by the eighth fixture; no arbitrary name, port or public dial.
3. Controls: numeric-local SOCKS5 ATYP=3 `t24-direct.invalid` through Direct:2081 and nonmatching Rule:2080 → exact local echo and at least one Direct UDP A receipt; zero Selected SOCKS, Group TCP or Proxy TCP DNS traffic and zero Node DNS traffic.
4. Group match: a Rule:2080 SOCKS5 ATYP=3 request for `t24-group.invalid:<echo>` must generate a real Group TCP DNS A receipt **and** an independent synthetic SOCKS CONNECT receipt to the **Group DNS TCP service port**, then one exact application response through DIRECT and **zero** Selected SOCKS app CONNECTs. The Group DNS Selected detour is a separate choice from the Group Direct application target; accepting the Direct application result never permits missing Group DNS A or Selected DNS-port CONNECT receipts. Proxy TCP, Direct UDP, Node UDP receive no extra queries. This prevents confusing a merely compiled group override with a real query or proxy detour.
5. Global Selected control: Selected:2082 SOCKS5 DOMAIN `t24-selected.invalid:<echo>` must generate a **separate** Proxy TCP DNS A receipt and independent SOCKS CONNECT to the **different Proxy DNS TCP port**, then precisely one Selected app echo (only for this separate global Selected control). Core may preserve the selected hostname or forward the independently answered Proxy DNS A=127.0.0.1 as numeric SOCKS target; both require the real Proxy A and SOCKS DNS-port receipts. Group TCP receipts must not change; Direct/Node resolver roles stay isolated. Count 1..12 bounded TCP DNS attempts per role, permitting legitimate retries/cache, but never accept missing A or missing SOCKS detour receipts.
6. Check immutable running Core PID/declaration+config revisions/Applied/LKG, zero denials or unexpected targets, explicit stop and listener closure in `finally`, approved artifact hash unchanged. Offline negative tests cover strict group declaration, wrong Group detour/role/match/port, wrong SOCKS hostname bytes, wrong or absent DNS and SOCKS port receipts, cross-roles, route bypass, Core PID/LKG changes and fixed safe diagnostic codes.
7. `T22_AIRGAP_GROUP_DNS_TCP_SELECTED_DETOUR=ok` is a bounded partial marker only when exact-head ordinary CI, Go Race 4/4, Managed Core Integration and both Linux native architectures all succeed; otherwise retain Draft and investigate failures.

## Non-claims

Earlier dual-native experiments using Group application target CurrentSelected with loopback A=127.0.0.1 did not produce an observable Selected app CONNECT; that path remains a separate unresolved routing/priority question. This proves one Group DNS binding and explicit TCP detour, **not** broad cross-layer priority, policy-change cache invalidation, remote/public DNS, UDP ASSOCIATE, CN 28 groups with licenses, T20 1,000 reconnects, T25 72h/7d/30d soak, physical power-loss recovery or stable release. Preserve `T22_HOSTNAME_AND_UDP_VERIFIED=false`, `T24_CN_RULESETS_OR_REMOTE_DNS_VERIFIED=false`, `T20_1000_RECONNECTS_VERIFIED=false`, `T25_72H_7D_30D_SOAK_VERIFIED=false`, `core_distribution=false`, `cn_preset_offline_bundle=false`. Stable main and release Draft PR #1 untouched.
