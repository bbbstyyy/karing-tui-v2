# ADR 0149 — Native network-none committed-generation Daemon-managed Core loopback traffic (T24 partial)

- **Status:** synthetic T24 preflight; does **NOT** certify offline release, real CN rules or production user recovery.
- **Depends on:** ADR 0145 CN provenance-only blocked redistribution, ADR 0146 native Daemon cold bootstrap, ADR 0147 independent Core SOCKS5 loopback and ADR 0148 configured-Core rejection without an Applied generation.
- **Unchanged scope:** ordinary-user native Linux amd64/arm64, no TUN/system proxy/route takeover, 28 CN preset groups + separate region append, Custom → GeoSite → GeoIP → ACL → FINAL, no subscription/ISP diversion layer.

## Previously untested gap

The prior network-none experiments isolated the production Daemon and verified the approved standalone Core separately. Even ADR 0148 configured the real Core path but intentionally did **not** apply a generation. None proved that the production **Unix Socket declaration commit → compilation → apply → persisted generation → CLI Core start → managed Core process → local selected-node TCP forwarding** path works without a nonloopback network route.

## Decision and method

1. Keep the first **three** native checks unchanged. Introduce a **fourth independent** readonly `docker --pull never --network none --cap-drop ALL --security-opt no-new-privileges --user 10001:10001` namespace using the previously pinned Python OCI index, throwaway `/work` private tmpfs and readonly staged approved Core and management binaries. As in ADR 0148, verify the staged Core's **architecture-specific original SHA-256 and ownership** inside the container; the connected host stages/built dependencies before isolation.
2. In `scripts/offline_lab/t24_airgap_managed_applied.py`, call the previous `ensure_airgap` nonroot/CapEff/no-route guard. Run an actual compiled management Daemon with verified `KARING_TUI_CORE_PATH`, private XDG/SQLite, and no previously stored declaration. A **local-only, synthetic V1 declaration** contains one SOCKS5 test node with numeric `127.0.0.1` and ephemeral port, no rule sets, CN preset, region append, external URL or DNS server. CurrentSelected points only to that local node, FINAL is DIRECT, and DNS is a never-used 127.0.0.1:53 fixture. No license-dependent assets are staged.
3. Over the **real Unix Socket HTTP API** (`POST /v1/declaration`, `POST /v1/declaration/compile`, `POST /v1/declaration/apply`), commit revision 1 with an expected-revision token, compile it, and apply a new generation with expected config revision 0. Require matching declaration/config SHAs, zero SRS resources, target revision 1 and a positive, persisted applied generation. Do not write database rows directly, substitute a mock compiler, or claim an artificial Core generation.
4. Explicitly `karing-tui core start` with the just-applied generation and verify the actual Daemon status says running, with the positive PID of a **same-UID child** executing exactly the approved pre-staged Core executable. Start an in-container ephemeral **127.0.0.1** echo server and a separate local SOCKS5 node that accepts **only 127.0.0.1:echo_port** and refuses all nonlocal requests. From the *three real managed* inbound ports `2080` (Rule), `2081` (Direct), `2082` (Selected), send full SOCKS5 CONNECT and distinct data payloads; require exact roundtrip. The selected path must traverse the synthetic SOCKS5 node, not accidentally be satisfied as a direct route.
5. Explicitly `karing-tui core stop`, verify durable STOPPED/no PID and no default proxy or control TCP listeners. Shut down Daemon cleanly. Restart the **same throwaway SQLite state** with no Core autostart, reissue an explicit start, verify generation identity and three local echo routes again, and require a second explicit stop and clean exit. Fresh network namespaces from the previous three tests and this new one are separate; neither is an actual host reboot or VM power interruption.
6. Standard CI runs fail-closed stdlib Python tests to refuse remote/wildcard nodes, invalid or extra routing/DNS/SRS fields, unauthorized Core state or generation, public ports, malformed API requests, unsafe local-node destinations and a workflow that drops one of the four isolated checks. Both native jobs must pass all **four** network-none probes at the final PR head together with normal CI/4 Race and approved Managed Core.

## Evidence boundary and remaining gates

Only **synthetic localhost traffic over a production Daemon-managed applied generation** is demonstrated. The synthetic node is not a real subscription and no remote destination is contacted; it does not exercise CN GeoSite/GeoIP/ACL resource loading, DNS resolution, actual public proxy servers, HMAC/credential restore, real VM identity/power events, two rollbacks, an offline install tar or soak. A connected CI runner obtains build dependencies and test OCI before the four network-none executions. The 68 logical refs / 67 source CN SRS resources / missing `geoip:bing`, copyright/licensing/attribution and distribution closure remain **blocked**. T15/T23/T24/T25 and 72h/7d/30d long-soak remain **OPEN**; `core_distribution=false`, `cn_preset_offline_bundle=false`, no release/restore/GC authorization. The stable `main` and outer Draft release PR #1 remain untouched.
