# ADR 0148 — Native air-gapped Daemon with a verified Core path but no applied generation

**Status:** T24 partial preflight, no production policy changes or release authorization. Depends on successful ADR 0146 real Daemon/SQLite network-none bootstrap and ADR 0147 independent real Core localhost SOCKS5 tests. Existing Linux non-root, no TUN, CN 28 preset groups, Custom → GeoSite → GeoIP → ACL → FINAL, no subscription/ISP routing layers unchanged.

## Gap

The prior network-none Daemon test deliberately left `KARING_TUI_CORE_PATH` unset, while the separate standalone Core test never involved the production Daemon. Thus CI did not verify the **production Daemon's approved-core artifact verifier**, private Core API control-secret persistence, no-applied-generation cold startup, explicit rejected start, or fail-closed invalid Core inputs under the same zero-egress conditions.

## Decision

- Add a **third independent** native amd64/arm64 container run to the pinned-image `core-provenance` matrix. It retains `docker --network none --cap-drop ALL --security-opt no-new-privileges --user 10001:10001 --read-only`, private tmpfs, and approved binary inputs. The connected **GitHub runner only**, not the unprivileged test container or product, changes the staged approved Core owner to root for compatibility with the production artifact verifier; fail if the final staged artifact SHA differs from the architecture-specific source lock. No new download or network call occurs inside the container.
- New `scripts/offline_lab/t24_airgap_managed_cold_guard.py` checks native arch, non-root UID, zero effective capabilities and no non-loopback route; binds staged Core bytes to the exact per-arch `resources/core.lock.json` SHA, with owner, size, mode, regular-file and single-link checks. The running Daemon's built-in verifier separately checks that same file before wiring the managed runtime.
- Using the actual compiled management CLI and a throwaway private XDG/SQLite store, configure **only** `KARING_TUI_CORE_PATH=/opt/t24/core` and start Daemon. Check the actual Unix-socket status: `core_configured=true`, `core_state=stopped`, persisted desired state `stopped`, no applied/LKG generation, no Core PID, no recovery, revisions zero; explicit CN bundle/Core distribution flags false. Require 0600 DB, 0600 Unix socket, 0700 directories and owner-only, single-link 64-hex-digit `core-control.secret` (return only its hash, never raw secret).
- Issue a **single explicit test-only** `karing-tui core start` without any applied generation. It **must fail**, must not start a Core process or open default loopback proxy/control ports, and must not populate Applied/LKG or change revisions. The current lifecycle intentionally can persist a failed desired-run intent before the failed command; this experiment therefore **always explicitly calls `karing-tui core stop`** to restore a durable stopped state before shutdown. Do not reinterpret failure as automatic stop or an authorized apply.
- Reopen the *same* throwaway SQLite state via a second Daemon process, confirm stopped/no generation persists, and that the control secret SHA is unchanged. A separate fresh throwaway runtime tries both an unapproved executable and an O_NOFOLLOW-disallowed **symlink** to the real approved Core: both must reject Daemon startup without leaving a listening Unix socket or creating a control secret.
- Fast stdlib Python unit regressions cover unsafe configurations, unintended Core PID/activation, wrong lock hash, symlink/hardlink/writable/oversized artifacts, unsafe secret permissions, open Core ports and the three distinct network-none workflow invocations. All checks must succeed on the **exact same SHA** on native amd64 and native arm64, together with ordinary CI/4 Race and approved Managed Core.

## Evidence limit

This verifies a **cold safety boundary** in a network-none process with a configured, approved binary but **no confirmed generation**. It does not run production managed Core from a committed generation, apply five-layer CN rules, launch external DNS or remote proxy traffic, import or distribute any unlicensed CN SRS, test a real offline release tar, perform backup/restore, actual VM power loss, double rollback or soak. ADR 0147's standalone Core local SOCKS5 test is separate and cannot substitute for a future fully managed generation traffic test. Maintain `core_distribution=false`, `cn_preset_offline_bundle=false`; T15/T23/T24/T25, known missing `geoip:bing`, CN source license provenance and 72h/7d/30d soaks OPEN. Stable `main` and outer release Draft PR #1 remain untouched.
