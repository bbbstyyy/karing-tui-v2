# ADR 0175 — native airgap Outbound/Node DNS UDP to fixed loopback SOCKS node

- **Status:** proposed M5/T22 partial native amd64+arm64 experiment. Does **not** close T22, T24 or release.
- **Depends on:** merged ADR 0174 Selected HTTP CONNECT hostname refusal/recovery and existing compiled Outbound/Node DNS role.
- **Isolation:** run a **fifth independent** Docker namespace on each native Linux architecture with the existing SHA-pinned approved Core, identical native management binary, `--network none --cap-drop ALL --security-opt no-new-privileges --user 10001:10001 --read-only` and ephemeral `/work` only. No changes to the original fourth container, its sixth Daemon/70 accepted session ledger or Core lifecycle.

## Gap

Earlier Selected SOCKS5/HTTP domain experiments prove **destination domain bytes reach the synthetic SOCKS upstream**. They do not test the actual **Outbound/Node DNS** path used when the *proxy node's server itself* is a hostname. A declared DNS server on 127.0.0.1:53 (without a running server) cannot count as real DNS traffic.

## Bounded design

1. Within the new isolated container create a fresh private SQLite/Unix socket, one local TCP echo and synthetic SOCKS5 node, and a **UDP DNS service bound to 127.0.0.1:0** (ephemeral unprivileged port, never port 53). A literal allowlisted declaration retains the current direct final, exactly one Selected SOCKS node and one `outbound` UDP DNS profile; only the SOCKS **node server** changes from numeric 127.0.0.1 to `t24-node.invalid` and DNS port becomes the actual ephemeral local server port. No public resolver, node, region rules, new fallback or subscription/ISP layer is accepted.
2. Run the production declaration API and native compiler, commit the generation and explicitly start the approved supervised Core. Client Rule:2080 and Direct:2081 numeric loopback SOCKS5 traffic must succeed **without** a synthetic Selected upstream connection or newly issued DNS lookup. Client Selected:2082 then sends numeric localhost SOCKS5 CONNECT/echo. Core must resolve **its own node server name** by a real UDP A question to the private listener, receive only `127.0.0.1`, connect to the synthetic Selected SOCKS node and deliver an exact application echo.
3. The DNS responder is strictly nonrecursive, bounded to 512-byte UDP questions and a fixed reserved `.invalid` hostname. It accepts one IN question (A, optional AAAA/HTTPS NODATA), optional strictly bounded EDNS metadata, logs only bounded raw qname/QTYPE receipts under lock, returns one local A record with a one-second TTL, and never dials any upstream. Malformed, other-name, compressed, malformed EDNS or nonlocal requests mark the fixture failed without resolving. Native acceptance requires at least one **real A receipt** on the approved hostname, no unapproved DNS traffic, **one** synthetic Selected upstream success, **zero** refusals and no responder/node fault.
4. Verify identical approved Core PID, config/declaration revision, generation and LKG before and after probes. Explicitly stop Core in a `finally`, verify stopped listener closure, secure hash of the pinned Core unchanged and all local threads terminated; Daemon itself exits cleanly. Negative no-Core tests cover exact DNS wire response, AAAA/HTTPS NODATA, invalid questions and destinations, strict local declaration, real UDP listener no-forward behavior, false DNS receipts, cross-route/bypass, new denial, PID/LKG drift and static diagnostics.
5. Only full exact-head CI (including Go Race 4/4), Managed Core Integration and native amd64+arm64 with actual packet receipts can emit `T22_AIRGAP_OUTBOUND_NODE_DNS_UDP=ok` from the fifth namespace.

## Explicit non-claims

This proves one **Outbound/Node DNS** UDP lookup through the approved Core in an artificial namespace. It does **not** prove destination Rule/Direct hostname DNS, Proxy/Group resolver detour, DNS over TCP/DoH/DoT, system DNS takeover, SOCKS UDP ASSOCIATE, real remote hostname, CN licensed five-layer/28-group SRS, T20 1,000 reconnects, T25 72h/7d/30d soak, physical power loss, Restore/GC or stable release. Keep `T22_HOSTNAME_AND_UDP_VERIFIED=false`, `T24_CN_RULESETS_OR_REMOTE_DNS_VERIFIED=false`, `T20_1000_RECONNECTS_VERIFIED=false`, `T25_72H_7D_30D_SOAK_VERIFIED=false`, `core_distribution=false` and `cn_preset_offline_bundle=false`. Do not add TUN or subscription/ISP routing and do not modify stable `main` or release Draft PR #1.
