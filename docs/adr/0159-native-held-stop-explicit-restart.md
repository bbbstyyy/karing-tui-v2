# ADR 0159 — T25 bounded explicit restart after stopping held SOCKS5 sessions

- **Status:** synthetic network-none early functional preflight only, not a production zero-drop restart, T25 72h/7d/30d soak, or release acceptance.
- **Depends on:** ADR 0149–0158, including the approved Linux native Core, actual Daemon Unix API and CLI, persisted Applied=LKG generation 2, three sequential explicit start/stop cycles, concurrent Rule/Direct/Selected traffic, controlled Selected refusal, and three live TCP tunnels that close on an explicit stop.
- **Unchanged envelope:** ordinary UID 10001, read-only root, cap-drop ALL, no new privileges and **four separate** `docker --network none` containers on each of native linux amd64 and arm64. No system DNS/network takeover, TUN, proxy-provider, subscription/ISP routing layer, remote endpoints, CN SRS, credentials or distributable resources.

## Gap

ADR 0158 validates that a deliberate operator `core stop` closes Rule, Direct and Selected *existing* TCP sessions and preserves stopped intent. Its sixth Daemon open only reads the persisted state, without actually starting a new Core after that session termination. We must also show that a fresh operator **start** on the **same Applied and LKG generation** can restore three fresh local proxy paths, survive a new synthetic Selected refusal without restarting the healthy Core, then stop cleanly again; a subsequent Daemon restart must never auto-start it.

## Decision

1. After ADR 0158 completes the fifth-Daemon three-cycle smoke and confirms all three held client sockets reached EOF or reset/abort, open the **sixth real Daemon** on the same private throwaway SQLite. Require persisted **stopped** intent, config/declaration revision 2, Applied=LKG promoted generation 2, no active transaction/recovery and an unchanged V1 declaration SHA. Verify all default proxy listeners are absent. No automatic Core start is allowed.
2. Perform **one explicit** bounded `core start` command. Require real management status `running`, unchanged revision/Applied/LKG, no circuit/recovery state, a positive Core PID and verified same-UID direct child running the exact approved/pinned Core executable. No candidate compile/apply is allowed during restart.
3. Relay fresh unique SOCKS5 echo payloads through Rule 2080, Direct 2081, Selected 2082; exactly one new Selected synthetic upstream CONNECT must occur and Rule/Direct must not cross it. Then inject **one** controlled local Selected CONNECT refusal, require Rule/Direct still relay successfully and Selected fails closed. Re-read real Daemon status and require the same running Core PID and Applied/LKG. Clear the refusal (existing fixture `finally`) and re-probe all three new paths with exactly one more Selected upstream CONNECT, still on the same Core PID.
4. Regardless of whether route assertions succeed, **if explicit start completed**, the test must invoke bounded explicit `core stop` in a `finally` block, wait for a persisted stopped state, verify PID=0 and all three default proxy listeners absent. Any cleanup failure is an experiment failure; it must never print success. In the normal success path, require the Selected synthetic node gained **exactly two** accepted relays and at least one refusal, with no bypass/error or still-enabled synthetic rejection.
5. Close the sixth Daemon; open the **seventh Daemon** on the same private SQLite **without issuing a start** and demand unchanged declaration SHA, Applied=LKG, stopped intent and no default proxy listeners. Verify total accepted synthetic Selected requests increased from 24 in ADR 0158 to **26**, rejected attempts increased to at least 11, and pinned Core hash remains unchanged.
6. Add no-network Python negative regressions for successful explicit restart/stop only once, persisted generation/sha drift, implicit restart rejection, Selected refusal affecting healthy routes, failed echo followed by mandatory cleanup, and no unexpected API changes. Print `T25_AIRGAP_HELD_STOP_RESTART=ok` **only after native success** on both architectures, and continue printing `T25_72H_7D_30D_SOAK_VERIFIED=false`.

## Native-test TCP teardown classification

A synthetic Selected SOCKS relay may observe `ECONNRESET`, abort or broken pipe **after successfully forwarding application reply bytes** when the already verified client tunnel is deliberately stopped or closed. The native test now treats only those specific post-reply peer closures as benign. A reset before forwarding any echo response, a failed CONNECT, a timeout, malformed destination or any other I/O error still marks the synthetic node unhealthy and fails the run. The client-side held-connection EOF/reset assertion and exact echo verification remain mandatory. Deterministic mocked-handler regressions cover both sides. The final stopped audit reports a fixed non-secret stage identifier to distinguish persisted status, port listeners, node accounting and Core hash failures.

## Boundaries and release holds

This experiment verifies a clean **explicit** restart after a **deliberately destructive** stop of only three localhost test sessions, not preservation of existing TCP streams, real network outage or DNS, physical power loss, corruption, two rollbacks, durable resource/credential restore, licensed CN 28-group/five-layer SRS or offline tar installation. It is not a measured long-duration stability or performance SLO. T15/T23/T24/T25 and M5 final release stay **OPEN**; `core_distribution=false`, `cn_preset_offline_bundle=false`; Restore/GC not enabled, stable `main` untouched and outer release PR #1 Draft.
