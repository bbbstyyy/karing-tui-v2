# ADR 0101 — Authenticated, read-only encrypted archive preflight

- Status: **M4 internal-only non-activating metadata preflight**; not a restore API or user-facing backup feature.
- Builds on ADR 0094–0100 and the fixed `docs/plan.md` §18.3 / T15 / T23 contracts.
- Linux ordinary-user execution, no TUN; CN 28 groups, Custom → GeoSite → GeoIP → ACL → FINAL, and subscription/ISP routing exclusion are unchanged.

## Decision

Add `backupclosure.PreflightInertArchive(ctx, archivePath, key, optionalCurrentClosure)` as a read-only internal function. It invokes the already-bounded `VerifyInertArchive` first: no output is returned until the full AES-CTR / HMAC-SHA-256 envelope, the canonical v1/v2 inventory, record lengths and every included database/rule/core SHA-256 have been checked. It then opens the same private path with `O_NOFOLLOW`, hashes the **entire ciphertext** again, and compares it with the authenticated archive receipt *before parsing* a separately buffered (≤128 KiB) inventory prefix. The descriptor, path inode, mode, size, modification time and context deadline are rechecked. A file changed between the authentication and report stages cannot be accepted simply because its first few encrypted bytes still resemble a valid manifest. The additional full-file scan trades performance for a simpler fail-closed no-plaintext-extraction boundary.

The returned `InertArchivePreflight` includes only fixed-format metadata: archive/inventory hashes and sizes, pinned storage schema, generation/rule counts and byte totals, whether an approved core is present, core architecture, and optional digest-count differences against a pinned current `Closure`. It never returns rule IDs, node names, subscription URLs, absolute paths, declaration bytes or credentials. Generations are compared by **content identity** (config/manifest/source-map SHA-256 and declaration revision), not their potentially reused database row IDs. Rules are compared by content-addressed, validated digest metadata. The caller's optional current closure is reverified both before and after archive inspection; absent it, no claim is made about current live state.

## Compatibility is not restorability

The inventory parser already rejects unsupported storage schema, unsupported versions/paths, invalid generation references and non-lock-approved core identities. A v1 archive has no approved core and receives the fixed blocker `approved_core_missing_from_archive`. An otherwise valid v2 archive from a different architecture receives `core_architecture_mismatch`; a local-architecture v2 may set `TargetMetadataCompatible=true` **only in the narrow sense that its inventory refers to the currently locked core identity and its included resource bytes verified**. The report **always** returns `RestoreSupported=false`, `RestoreReady=false`, and explicit blockers `transactional_restore_not_implemented` and `sqlite_logical_restore_validation_not_implemented`.

This preflight does not deserialize or query the backup's SQLite database: its claims about migrations, declarations and generation bindings are based on the authenticated writer's inventory and payload digests, **not on independent relational integrity validation on import**. A later restore protocol must do full SQL schema/quick_check, immutable generation and routing/DNS binding checks, authenticated private staging, actual core Check, CAS apply, rollback-of-rollback and fault injection. It must also establish a fresh durable lease on the source and backup candidates before activation. The output of this preflight cannot be used as an authorization token or handed to the existing apply coordinator.

## Tests and non-goals

Regression tests cover an encrypted v1 roundtrip with an optional unchanged current snapshot, changed generation/rule digest counts, unrelated stores reusing generation row IDs, credential/path redaction, wrong key, malformed or symlinked ciphertext, canceled context, tampered current closure, and a mutation deliberately injected **between successful authentication and the metadata re-read**. Managed-core integration also exercises the real locked v2 core archive and checks the report remains explicitly non-restorable. No daemon/CLI/TUI endpoint, plaintext extraction, file write, backup import, schema migration, restore or restart is enabled. T15/T23 and all M4/M5 release gates remain open.
