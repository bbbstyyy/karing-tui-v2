# ADR 0143 — Independent non-destructive host running observation after manual disposable VM restart

- **Status:** M4 guest-only/read-only T15/T23 laboratory sub-evidence. NOT a real VM reboot certification, power-loss acceptance, Core health proof, archive authentication, restore/GC authority, public API or release gate.
- **Depends on:** ADR 0128 `vm_power_cut.py` (explicit host force-stop, never CI), ADR 0142 guest v11 phase→durable intent→observed stop, and the full real Go SQLite v18 guest subset ledger.
- **Product constraints:** ordinary-user Linux, no TUN; retain CN 28 presets, Custom → GeoSite → GeoIP → ACL → FINAL; no subscription/ISP routing rules.

## Missing link

ADR 0142 requires durable pre-stop phase+intent+observed-shutoff continuity, but has no separate observation after the operator *manually restarts* the disposable VM. Consequently the guest's `verify` could accept matching SQLite and original host stop receipts even when no later host libvirt "running" state had been observed. The extra observation must remain strictly non-authorizing: same-domain `running` alone cannot prove a kernel or daemon actually booted, all disk writes survived a physical outage, or the same guest OS rather than merely a libvirt definition returned.

## Decision

1. Add **`scripts/recovery_lab/vm_postboot_observe.py`**, a separate host-side **non-destructive** observer. It never invokes `start`, `destroy`, `shutdown`, `sudo`, `qemu:///system`, a Core process, real network requests, or SQLite write APIs. Default mode is **preview only, no file writes**. Explicit `--record` requires an ordinary non-root user and an exact per domain/UUID/case/nonce/**externally pinned pre-stop baseline SHA** `KTUI_LAB_VM_POSTBOOT_ACK`. An already published receipt is never replaced.
2. Require the existing owner-private `0700` per-nonce witness directory and exact `ready-<nonce>.txt`. Read its real bytes through `O_NOFOLLOW`, owner/0600 or 0400 and single-link checks; read the guest's **v12** pre-cut baseline and both original fsynced host `intent` and `observation` records through bounded descriptor-relative `O_NOFOLLOW` reads. Reject changed identity, duplicate JSON keys, NaN, noncanonical UTC timestamps, changed marker, reversed intent/stop chronology, already used nonce, unknown JSON fields and escalated flags. Require the supplied **external** SHA to match the original baseline rather than recomputing and accepting the current guest witness as authoritative.
3. Query **only** `virsh --connect qemu:///session domuuid` and `domstate` for the exact pinned domain, require matching UUID and `running`, then recheck the pinned pre-stop record set and identity before writing a new `poststart-<nonce>.json` as a single owner-only `0600`, no-follow, O_EXCL fsynced file (directory fsynced). Preserve the *raw* SHA-256 of the original intent, observed-stop and baseline documents, marker digest, domain/UUID/case/nonce and UTC observation time. Refuse when current host clock precedes the original stop; clocks are **not independently trusted**.
4. Extend the guest audit **witness v11 → v12 only**; production SQLite stays **v18**. The same read-only SQLite-before/after modes now require the exact original host `poststart` row, all expected SHA links and strict `false` booleans for boot, consistency, power-loss, Core, HMAC, restore and deletion. Re-read the marker and all host records before returning a success and reject any drift. Report only `host_running_observation_checked=true` as **local record continuity**, never `guest_reboot_verified` or `physical_power_loss_verified`.
5. Synthetic Python tests exercise actual host stop writer and new poststart observer via **mock libvirt only**, with a separately simulated manual restart and genuine v12 guest reader; negative tests cover missing/forged/torn/duplicate/misordered receipts, a hostile host domain/UUID, wrong external baseline SHA, no ACK, privileged invocation, symlink/hardlink/public permissions and attempted overwrite. A separate real Go v18 SQLite/Python cross-language fixture verifies a valid synthetic chain and refuses a removed running-observation receipt even when Applied/LKG and source records are intact.

## Out of scope / release blockers

No CI actually starts/stops a virtual machine or has an operator-controlled disposable VM identity. This chain can be fabricated by the same local host user and does not prove a genuine guest OS boot, hypervisor boot sequence, electrical power fault, underlying storage fsync durability, Core Check/Activate/Verify, actual DNS/routing health, archive HMAC, imported credential recovery, rule-file cleanup or a second rollback. No public backup/restore/delete operation is added; all powers remain false. To run real T15/T23, a separate authorized operator must prepare a truly disposable VM at a genuine fsync checkpoint, independently pin the baseline SHA, run host stop once, **manually** restart the VM, observe running, inspect guest state and Core/resources, and collect independent evidence. T15/T23/T25, CN offline license/provenance and 72h/7d/30d stability remain **OPEN**. Do not re-use or upgrade older v11 witnesses or merge to stable `main`; outer PR #1 remains Draft.
