# ADR 0157 — T25 native parallel Selected refusal under healthy Rule/Direct traffic

- **Status:** synthetic, bounded T25 early-warning preflight; not formal 72h/7d/30d soak, production outage acceptance, real external proxy failure, or release approval.
- **Depends on:** ADR 0149–0156, especially the real Linux native managed Applied/LKG generation, three explicit Core lifecycle cycles, successful 6-client/12-echo three-inbound parallel batch, and a strict bounded synthetic Selected SOCKS5 node.
- **Unchanged sandbox:** fourth of four independently isolated `docker --network none` containers on native amd64 **and** arm64; UID 10001, cap-drop ALL, no-new-privileges, read-only root, private SQLite and numeric localhost-only echo/upstream. No TUN, external DNS, real CN rulesets/remote proxies, subscription/ISP routing layer or user data.

## Motivation

ADR 0156 proves that all three inbound ports can concurrently relay successful traffic with four exact Selected-only audit payload tags. ADR 0151 tested a single Selected SOCKS5 CONNECT refusal while Rule/Direct succeeded **sequentially**. Neither demonstrates that multiple overlapping selected failures cannot interrupt simultaneous healthy Rule/Direct clients, cause fallback through Direct, or restart a healthy Daemon-managed Core. The two tests combined do not establish safe failure isolation under a mixed concurrent request batch.

## Decision

1. Within ADR 0156's already-approved **third and final managed Core lifecycle cycle**, first finish the existing healthy six-client/12-request localhost batch and check its exact four Selected audit payload tags. Keep the same Core PID and generation 2.
2. Enable the **test-only** `reject_connections` switch on the synthetic 127.0.0.1 Selected node. Simultaneously launch six clients through a bounded eight-second barrier, **two workers per Rule:2080, Direct:2081, Selected:2082**; each worker makes two bounded requests. Rule/Direct's **eight** requests must each complete a distinct full TCP SOCKS5 echo; Selected's **four** requests must receive an explicit SOCKS refusal or close without success (no CONNECT success or direct fallback). Capture all worker exceptions through futures with a strict 40-second limit and fail the test.
3. During the refused batch, require the Selected node accepted **zero** successful relays, recorded between 4 and 16 denied upstream CONNECT attempts (allowing bounded legitimate retries without tolerating storms), recorded no new successful Selected payload tags, and reported no fixture failures. All other inbounds must still work; a missed denial, accidental Direct fallback, refused Rule/Direct or unexpected Selected success rejects the experiment.
4. Recheck **actual** Daemon status with the same running Core PID, declaration/config revision 2, Applied=LKG generation 2, healthy no-recovery/no-circuit state. Clear the synthetic refusal switch **in a finally block on every exit**. Run the full previous six-client/12-echo batch **again**, requiring its four exact new Selected-only payloads, the same Core PID and no additional rejection. Then keep prior explicit Core stop, no-listeners/FD checks, final SQLite restart/stopped intent and locked Core hash.
5. Add standalone fast stdlib regressions for 8 Rule/Direct successful, distinct payloads and 4 Selected denials under overlap, invalid ports and poisoned node counters, a missing/refused Selected rejection, an accidental Rule→Selected hop, a denial storm over 16, a fixture error, direct success on Selected, a healthy-inbound failure, and unconditional refusal-switch cleanup. Update the three-cycle fixture assertions to call healthy→refusal→healthy on cycle 3 only.
6. Keep all prior T24 markers, append `T25_AIRGAP_PARALLEL_REFUSAL_ISOLATED=ok` **only after** the real native sandbox exits successfully, and always append `T25_72H_7D_30D_SOAK_VERIFIED=false`. Exact-head ordinary Go/Python/build/format, Race 4/4, Managed Core integration, native amd64+arm64 Core Provenance (each with all four isolated containers) remain mandatory before merge.

## Evidence boundary

The test uses a **synthetic application-level SOCKS5 refusal**, not physical disconnection, packet loss, actual CN five-layer SRS/rules, real DNS/GeoIP, remote subscription, multihour load, p99 latency, user session preservation, power loss, corrupted disk, double rollback, full archive credential restore, licensed redistribution or offline tar installation. It provides **no** T25 soak result. T15/T23/T24/T25 and M5 release remain OPEN; `core_distribution=false`, `cn_preset_offline_bundle=false`, Restore/GC unchanged; stable `main` untouched and outer PR #1 Draft.
