# ADR 0146 — Native amd64/arm64 air-gapped ordinary-user bootstrap (partial T24)

- **Status:** T24 **partial preflight only**; release, offline CN bundle, complete proxy runtime and full T24 acceptance **NOT authorized**.
- **Depends on:** approved reproducible project-owned Core build from `resources/core.lock.json`; ADR 0145 bounded, provenance-only CN resource audit with unresolved redistribution licenses.
- **Unchanged requirements:** Linux ordinary user; no TUN/TPROXY/route takeover/system proxy mutation; CN 28 presets and separate region append; Custom → GeoSite → GeoIP → ACL → FINAL; no subscription/ISP diversion.

## Gap

The project has reproducible approved Core binaries and ordinary-user **connected-host** smoke on native amd64/arm64; generic Go CI tests do not actually start the resulting management binary and SQLite/Unix socket with **no network**. T24 requires a disconnected offline startup check, not mere cross compilation. It remains blocked for CN resources and licenses, but a smaller network-disabled bootstrap can be verified now without including or redistributing unknown-licensed data.

## Decision

1. Extend `.github/workflows/core-provenance.yml` from its existing native **amd64**/`ubuntu-24.04` and native **arm64**/`ubuntu-24.04-arm` approved-Core build+host smoke jobs. In each native runner, the pinned Go **1.25.12** Core build script checks exact version/build tags, hashes and executable behavior, then exports the unchanged approved Core artifact. Switch to pinned Go **1.27.1** to compile the project management CLI with `CGO_ENABLED=0` for that runner architecture.
2. Stage only the two executables and the readonly test script **before** isolation. Pre-pull `python:3.12-slim-bookworm` on the CI **host** and log the resolved OCI image digest. The tag is not yet pinned as an immutable release input and this stage is intentionally NOT release-reproducibility proof.
3. Run `scripts/offline_lab/t24_airgap_bootstrap.py` in a Docker container using `--network none`, ordinary UID 10001, `--cap-drop ALL`, `no-new-privileges`, read-only root filesystem, a private 0700 tmpfs, and read-only mount for the staged binaries. No network source, registry, module, or rule data download occurs **inside the container**. The test rejects residual effective Linux capabilities, architecture mismatch or a non-loopback IPv4 route. An OCI daemon is used by CI to create this namespace, **not** by the ordinary-user application.
4. In the isolated namespace, verify the approved Core version and run **only its config `check`** on the project-known local three-loopback-Mixed-inbound/no-TUN/no-rule-set config. **Do not start Core**, assert traffic, connect to remote DNS/proxies or claim the SRS set is present.
5. Start the actual management Daemon with no configured Core path and private XDG config/data/state/cache/runtime paths, inspect `status --json` and `capabilities` over its **Unix** socket, assert SQLite `0600` / socket `0600` / directories `0700`, stopped Core desired state, no applied/LKG generation, no recovery required, and explicit `core_distribution=false`, `cn_preset_offline_bundle=false`, `cn_preset=false`. Stop with SIGTERM, launch it again on the **same isolated SQLite state**, and verify revision/state continuity and clean stop. This validates a native Linux disconnected *management-plane bootstrap*, **not** an offline proxy session.
6. Add quick Python negative-policy tests to the standard CI: prohibit an active Core, a persisted applied generation, failed recovery, unapproved distribution capability, invalid version and accidentally added TUN/ruleset in the inert Core configuration. Any failing native architecture job blocks this **preflight**. No new product API, migrations, automatic recovery, package distribution or license claim is introduced.

## Remaining T24 / release blockers

The Docker test stage may access the internet to fetch its OCI image and build dependencies **before isolation**; the only guaranteed air-gapped portion is the non-root process inside the network-none container after staging. It does **not** test a tar installation or existing applied generation, runtime Core connect/check/activate/verify, real DNS / proxy routing, Karing CN preset resource availability, complete approved attribution/licensing, or genuine offline update/rollback. The test runtime image tag also needs a frozen digest before a reproducibility claim. The known `geoip:bing` absent input remains unresolved, the source 67-file CN closure is not redistribution-approved, and app/core packaging names/licenses need review. T15/T23/T24/T25, both full arch offline release packages and 72h/7d/30d soak remain **OPEN**. Stable `main` and outer Draft PR #1 remain untouched.
