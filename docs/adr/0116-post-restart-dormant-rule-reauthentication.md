# ADR 0116 — Post-restart independent authentication of inactive rule bundles

- Status: **M4 internal, read-only authentication prerequisite**. This is not a durable rule resource lease, garbage collection, a backup restore API, active resource publication or any form of Core execution.
- Extends ADR 0107–0115; SQLite storage schema remains **v18** and no existing archive, rule, journal or daemon runtime format is changed.
- Linux ordinary user; no TUN, CN original 28 presets and Custom → GeoSite → GeoIP → ACL → FINAL. Subscription/ISP routes remain excluded.

## Problem

ADR 0114 can atomically publish a rule-only directory into a private inactive namespace. ADR 0115 can inventory orphan and published-looking names after a crash but cannot authenticate contents: an existing directory name, even one containing a ciphertext digest, is untrusted. The original ADR 0113 anonymous `O_TMPFILE` pins disappear on Close, SIGKILL and restart. A future explicit cleanup or import decision cannot rely on a vanished pin, an audit receipt, a bare filesystem path or the presence of a manifest-like basename.

## Decision

Add `InertRestoreResourceLease.AuthenticateDormantRuleBundle(ctx, key)`, returning only an `AuthenticatedDormantRuleReport`.

1. **Start from a newly acquired ciphertext lease, not the private directory.** The caller independently opens the existing encrypted candidate by exact v18 pending journal ID, reacquires its ciphertext directory `flock`, and supplies the 32-byte key. The method holds this lease mutex across all checks and repeats complete ciphertext HMAC/SHA, archived SQLite/schema/profile verification and live Applied/LKG/declaration/selection/Core/journal CAS. Wrong keys, abandoned records, closed leases and stale live selections fail closed.
2. **Derive the only possible inactive root** as `<live-state-db-parent>/inert-rule-bundles`. No caller-controlled scope name, source path, target root or destination is accepted. Require existing UID-owned 0700 parent and take the same exclusive `flock` used by ADR 0114's publisher. Refuse overlapping candidate namespaces, symlinks, unexpected root entries, unsafe modes, unknown/pending directories or more than eight completed scopes. A pending directory must be handled by an **independent**, future operator-directed procedure.
3. **Bind to the authenticated inventory.** Read the inventory through the current ciphertext lease, require 1–128 canonical rules and a 128 MiB total limit; select only `.ktui-inert-rules-v1-<exact-ciphertext-sha>`. The selected bundle must contain exactly the inventory-listed `<sha>.json|.srs` leaves with the exact size/count, UID ownership, one link and 0400 non-executable mode. No historical core executable, credential SQLite file, extra rule, symlink or hardlink may be present.
4. **Verify real bytes, not names.** Open directory and files using parent-relative `O_NOFOLLOW`, retain in-process inode identities and hash each rule from its own FD, checking the full exact SHA-256 and byte count. Reopen directory FDs and repeat entire namespace/inode checks, rerun authenticated candidate/journal/live CAS, rehash every leaf, and finish with another scope/root identity and permissions check. Test-only mutation hooks exercise replacement with same bytes, modified bytes, late extra files and live journal/selection drift.
5. **Return evidence, never authorization.** Only ciphertext/inventory/scope digests, rule count/bytes and `RuleBytesVerified=true` are returned on a successful in-call authentication. `Inactive=true`, `RequiresRevalidation=true`, `RestoreReady=false` and `RestoreSupported=false` always apply. Reports expire immediately after return; no FD or immutable trust token survives. A later cleanup/import must take fresh locks, independently authenticate again and execute its own transaction-bound CAS and rollback contract.
6. **Read-only behavior.** This function performs no mkdir, copy, rename, unlink, fsync, SQLite writes, rule-store insertion, Core Check/Run/Activate, generation creation or restoration. A failed authentication returns an entirely empty report. Same-UID actors can race paths after the function returns; this is intentionally not a cross-process durable lease or file-system transaction.

## Verification and deferred gates

- Tests stage a private completed bundle, drop the original anonymous resource pins/ciphertext lease, reopen SQLite with a fresh client and independently reacquire the encrypted candidate. They verify exact positive hashes, wrong key, closed lease, symlinks, hardlinks, missing/extra rule files, same-length byte tampering, permissive modes, pending scopes, unknown directories, root replacement, late same-byte inode substitution, selection/journal drift and cancellation.
- A separate Linux subprocess reacquires and reauthenticates the same dormant data, is SIGKILLed while holding the lease, and the parent independently reacquires/reauthenticates the ciphertext and disk rule bytes again, without changing the live applied generation.
- **Still outstanding:** operator-directed orphan inventory/abandon and inode-exact cleanup; a cross-restart durable resource authorization protocol; active resource installation, SQLite and credential migration, compiler parity, atomic restore journal/write CAS, Core Check/Activate/Verify, rollback-of-rollback, crash/power-loss fault injection, offline CN resource licensing and 72-hour/7-day/30-day stability evidence. PR #1 remains Draft and all backup/restore user-facing commands stay disabled.
