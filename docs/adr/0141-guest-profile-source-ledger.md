# ADR 0141 — Bounded complete profile-source/lease/usage ledger in disposable guest replay

- **Status:** M4 Linux ordinary-user disposable guest **read-only** T15/T23 subset, not a recovery permission or release gate.
- **Depends on:** ADR 0139–0140 guest v8/v9 snapshots and user-overlays; production Go v18 `profile_sources` schema and profile source CAS/update/scheduler contracts (ADR 0058–0062, 0064, 0066).
- **Non-negotiable product constraints:** Linux, no TUN, preserve CN's 28 preset groups and Custom → GeoSite → GeoIP → ACL → FINAL; subscription/ISP routing stays excluded (imported proxy nodes are separate).

## Gap

A source can exist **before any accepted snapshot**. `profile_sources` persists independent remote subscription URL or local path, fetch-target identity, filter and schedule, last HTTP and failure/retry status, update lease and subscription usage metadata. Guest v9 pinned snapshots and node overlays, but changing a source URL, retry deadline, lease or usage value without advancing the source CAS revision left those ledgers untouched. An independently pinned witness must detect this without revealing credentials or treating digest equality as authenticated remote content.

## Decision

1. Advance only **disposable guest witness v9 → v10**, not the production SQLite v18 schema. A v9 witness cannot be overwritten, upgraded or silently reused; start a fresh disposable VM owner-private directory/nonce and preserve its externally pinned SHA-256.
2. Read exactly **all 33 production `profile_sources` columns**, explicitly enumerated in the same WAL-aware SQLite **read-only** transaction that covers generation, declaration, snapshot, overlay and journal evidence. Order by profile ID; reject duplicate/nonmonotone identifiers. Source records need **no corresponding `profile_state`** because Go permits a source before a snapshot, and snapshots may predate a source.
3. Validate Go-shaped fields conservatively: stable profile ID, positive source CAS revision, known source formats, HTTP(S) URL without embedded userinfo or a clean absolute Linux path, valid fetch-mode/node reference combinations, filter mode/expression, enabled bool, permissible URL-only update interval, bounded UTF-8 source/HTTP/error text, bounded offset-aware timestamps, nonnegative usage/counters, matching subscription observation fields, and active lease ID/time pairing with the production 1–128 `[A-Za-z0-9_.:-]` lease identifier. In addition to the source model, refuse duplicate lease IDs, inconsistent or malformed stored values. This checks **shape and drift only**, not live source ownership, remote bytes or the state of external servers.
4. Bound inspection to **64 total source rows**, a guest-only fail-closed limit, not a new production quota. Hash all raw SQL values (including NULL vs empty string, source URL, HTTP cache validators, filters, usage and lease) in a stable ordered canonical JSON digest with explicit v10 domain separation. Put **only** `profile_source_record_count` and `profile_source_ledger_sha256` into the private witness; never export source locations, tokens, remote revision, ETag, filter, failure strings, or profile IDs as plaintext in witness/report/errors.
5. Strict `verify` and the narrow prepared→interrupted `reconcile-verify` both require unchanged source ledger. Independent `RecoverInterruptedProfileUpdates` can legitimately clear update leases and record errors, but **this narrow T15 prepared-apply comparator does not authorize that change**; such fixtures must fail closed for separate manual review instead of being silently reconciled.
6. Python synthetic regression covers empty source, valid URL source without any snapshot, unchanged SQLite during audit, URL/token drift, retries and subscription usage, active lease clearing, malformed field/lease shapes, 65th row refusal, and prepared-only journal comparison rejecting a filter change. Go/Python cross-language tests use the real production Store to `CommitProfileSource`, `BeginProfileUpdate`, `FinishProfileUpdateSuccess/Failure` with subscription usage and retry, then pin the original Python witness and detect changes to source URL or use counters despite unchanged CAS. Another real Go fixture confirms post-restart lease reconciliation is **not** silently accepted as a prepared apply-only transition.

## Exclusions and remaining gates

This does not authenticate subscription provider responses, metadata authenticity, DNS reachability, profile fetch health or any remote secret; plaintext URLs are not exported. It does not execute a real VM stop/reboot, power interruption, Core network flow check, HMAC-authenticated archive restore, credential-preserving backup, resource deletion, production migration, or long soak. T15/T23/T25 and CN offline rule redistribution/license remain OPEN; `RestoreSupported=false`, `RestoreReady=false` and all guest restore/deletion approvals false. Outer PR #1 remains Draft; stable `main` unchanged.
