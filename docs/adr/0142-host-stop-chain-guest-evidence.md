# ADR 0142 — Guest v11 independent binding to VM phase marker and durable host stop receipts

- **Status:** M4 disposable T15/T23 **guest-only** read-only preflight. It never stops/boots any VM, contacts live Core, restores an archive, deletes state, or grants T15/T23 acceptance.
- **Depends on:** ADR 0128 host `vm_power_cut.py` and its pre-stop `ready-<nonce>.txt` marker; ADR 0129–0141 v10 WAL-aware Go SQLite v18 guest audit.
- **Preserved constraints:** non-root Linux, no TUN, CN 28 preset groups, Custom → GeoSite → GeoIP → ACL → FINAL, no subscription/ISP diversion layer.

## Problem

Until v10, guest `capture` pinned only the logical SQLite state. Later `verify` checked a single `observation-<nonce>.json` stop receipt with some matching identifiers, but **not** the durable host `intent-<nonce>.json` or the original phase-ready marker content. A missing/forged host intent or swapped ready marker could therefore be invisible when SQLite, selection, profile and all prior ledgers matched. The already-existing host producer always writes an owner-private, fsynced intent before the deliberate user-session `virsh destroy`, then an observation only after independently reading `shut off`. The guest should require that complete chain.

## Decision

1. Advance only the disposable guest **witness format v10 → v11**. Do not modify production SQLite **v18** or migrate/reuse an independently SHA-pinned older baseline. All earlier witnesses stay separate, immutable experiment records.
2. Before `capture`, inspect the existing `ready-<nonce>.txt` through the same owner-private witness-directory descriptor, using `O_NOFOLLOW`, `0400/0600`, uid/nlink/regular-file checks and twice-checked inode, size and mtime identity. Require exact `vm_power_cut.marker_body(case,nonce)` bytes and fixed 256-byte limit. Pin **`phase_marker_sha256`** into the v11 private baseline. The marker must be written only by a genuine disposable guest test fixture at the chosen durable checkpoint, not manually fabricated as evidence.
3. On `verify` and narrowly scoped `reconcile-verify`, require the original **externally pinned baseline SHA**, exact v11 marker hash, plus **both** owner-private `intent-<nonce>.json` and `observation-<nonce>.json` through descriptor-relative `O_NOFOLLOW` reads (each capped at 4 KiB, single hardlink, uid and mode checks, no path traversal). Require the host tool's **exact** schema/keys and `schema_version=1`, status sequence `intent_before_forced_virtual_stop` → `virtual_guest_forced_off_observed`, bound case/domain/lowercase UUID/nonce and baseline marker SHA, every power/boot/restore/deletion flag strictly `false`, and canonical UTC offset timestamps with observation not preceding intent.
4. Reread both host receipts and compare raw content digests before returning any successful subset comparison to detect changes during the guest audit. Refuse missing/duplicate, malformed, wrong permissions/link, mismatched marker/UUID/case/nonce, reversed UTC timestamps, extra keys and escalated authorization flags. No repair, re-pin, retry, VM action or metadata deletion is allowed.
5. A new synthetic Python test exercises the **actual host `vm_power_cut.run_case` writer** through a mock libvirt runner (not real `virsh`) and the unmodified guest v11 reader, asserting read-only SQLite main bytes and all release/restore flags false. Adversarial tests vary marker bytes, delete host intent, tamper receipt identity/time/flags, add fields, relax permissions or add hardlinks. The real Go v18 SQLite/Python bridge now supplies the same synthetic marker plus two host-shaped receipts and independently proves a missing intent cannot be excused by matching Applied/LKG and other SQLite contents.

## Evidence boundary

This establishes **only syntactic, private-file and local hash continuity** between a guest checkpoint marker, the host intent/stop-observation files and the guest's SQLite baseline. The host user can still fabricate these files; a timestamp is not a trusted clock or hypervisor attestation. The produced Boolean `host_stop_chain_checked=true` means *shape and digest continuity only*. `guest_reboot_verified=false`, `physical_power_loss_verified=false`, `core_health_verified=false`, `archive_hmac_verified=false`, `restore_authorized=false` and `metadata_deletion_authorized=false` remain mandatory. No real VM was stopped or restarted in CI. Full T15/T23/T25, postrestart Core/rule/credential checks, CN offline resource license closure, physical-device replay, rollback-of-rollback and 72h/7d/30d soak remain **OPEN**. Stable `main` and outer Draft PR #1 are untouched.
