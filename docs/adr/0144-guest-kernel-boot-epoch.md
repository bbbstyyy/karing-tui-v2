# ADR 0144 — Independent Linux kernel boot-ID continuity evidence for disposable T15/T23 guest

- **Status:** M4 laboratory-only, read-only before/after evidence. **Not** T15/T23 acceptance, verified guest reboot, real power loss, Core/routing health, archive HMAC, restoration or metadata deletion.
- **Depends on:** ADR 0142 durable phase→host intent→observed-off, ADR 0143 host poststart `running` observer, and guest v12 pre-cut SHA-pinned SQLite subset.
- **Unchanged production:** Linux ordinary-user without TUN, CN 28 preset groups, Custom → GeoSite → GeoIP → ACL → FINAL, no subscription/ISP diversion, SQLite schema v18, stable `main` untouched.

## Missing evidence and decision

A libvirt user-session domain being observed `running` after a synthetic or real host stop does not establish that a *different Linux kernel boot* took place. Introduce a **separate**, guest-only `scripts/recovery_lab/guest_kernel_boot_epoch.py` with a fixed **boot-epoch witness schema v1**, **without modifying guest SQLite baseline format v12**.

1. **Before the stop:** Immediately after existing `guest_reboot_audit.py --mode capture` and before publishing any host stop intent/observation, the ordinary-user guest runs `guest_kernel_boot_epoch.py --mode capture --baseline-sha256 <original external SHA>` under the same exact XDG per-nonce witness and explicit `GUEST_AUDIT` acknowledgement. Read **the real Linux procfs** `/proc/sys/kernel/random/boot_id` through `O_NOFOLLOW`; accept only canonical lowercase nonzero UUID. Check the private pre-cut marker and that the guest's original **v12 baseline SHA is externally pinned**, that no old host stop/poststart receipts already exist, then create one durable, non-overwriting `boot-epoch-<nonce>.json` with `O_EXCL/O_NOFOLLOW/0600`, file+directory fsync. Return its SHA for **independent storage outside the guest**. The pre-stop boot UUID is private, never printed by the CLI.
2. **After independently operating the disposable VM:** Only *after* the separately authorized host stop, operator-manual restart, and ADR 0143 `poststart` receipt, run `--mode verify` with **both** original externally stored SHA strings. Reopen the original epoch receipt through a directory descriptor, validate owner, single-link, mode, bounded content, duplicate-key-safe JSON, complete exact schema, case/nonce/domain/UUID, original v12 baseline and marker hashes and strictly false privilege flags. Read the real Linux kernel boot UUID and **require it differ** from the one pinned before the stop. Recheck procfs ID, original externally pinned records and entire host stop→running chain before returning.
3. Fail closed for unchanged/malformed boot ID, missing/mismatched offline SHA, forged/removed epoch record, stopped/replayed experiment nonce, missing poststart, wrong host identity or any record drift. An interrupted or incomplete capture may leave a partial private file; **do not re-run with the same nonce**. Only the new script's **`kernel_boot_identity_changed_observed=true`** means local procfs appeared to have a different boot identity. `guest_reboot_verified=false`, `physical_power_loss_verified=false`, `core_health_verified=false`, `archive_hmac_verified=false`, `restore_authorized=false`, `metadata_deletion_authorized=false` remain mandatory. The boot-epoch script does **not** claim an SQLite check; the earlier guest v12 `verify`/`reconcile-verify` must run independently.
4. Production CLI provides **no boot-ID override or injectable path**. Python synthetic tests replace the internal reader only inside the test process and invoke the **actual mock-libvirt host writer/poststart observer**. A Linux Go cross-language test uses real v18 `storage.Open`/Applied/LKG data and **the actual process procfs**: its unchanged CI boot ID must **fail**, even with synthetic host receipts and unchanged SQLite.

## Evidence boundary and remaining work

Kernel boot UUIDs can be observed in containerized or operator-controlled contexts and are not cryptographically signed by a hypervisor or TPM. A changed value plus host stop receipts still does not independently prove authentic guest identity, physical electrical loss, complete disk durability, Core traffic, rollback-of-rollback, credential-safe restore, licence-compliant CN rule distribution or a trustworthy clock. CI **never** actually stops or starts any VM, never changes real VM power, and does not set `guest_reboot_verified=true`. T15/T23/T25, true operator-run VM/power-loss replay and live post-boot Core/rule/backup/credential checks, CN offline licensing and 72h/7d/30d soak remain **OPEN**. Preserve previous immutable guest v12 baseline and stop/poststart receipts; do not recapture missing evidence or authorize restore/GC.
